All work now uses C:/dev/creator_agent, as directed by Jordan. Branch: codex/audit-boundary-fixes, from main 1cf6d63 (audit PR #40 merged). The original report remains a historical record of commit 7fd1369. This repair covers its four findings only.

## Changes

1. **Held-out answers:** the execution supervisor writes only argv and stdin to the runtime input mount. Expected stdout, exit code and case labels remain in the supervisor records. The bridge refuses legacy/full QA JSON before mounting it. Expected cases, comparison rules and protocol decisions are unchanged. The bridge hash changes; old execution evidence does not authorize new execution and affected packages require reverification.
2. **Invalid signatures:** rejected, unauthenticated payment webhook requests no longer insert database receipts. Replies still explain rejection; signature-verified events retain durable economic receipts. This removes the unbounded unauthenticated write path without inventing a retention policy for attack payloads. Public deployments still require proxy rate limiting for inbound traffic and database reads.
3. **Payment reads:** a short transaction records a monotonic observation epoch per connection, then releases its database connection before processor I/O. The projection transaction rechecks ownership, active connection state and epoch under its existing financial/connection locks. A newer started observation fences an older completion (even if the newer read subsequently fails). Owner requests receive VERSION_CONFLICT and must retry; webhooks return 503 with a deferred receipt. The fence is intentionally conservative across objects on one connection. Payouts and balances use the same rule. A late failed balance read cannot invalidate a newer observation. No unbounded automatic read retry is added.
4. **Batch files:** output/error streams enforce an 8 MiB per-file limit, 256 KiB per line and 10,000 lines; retained results are restricted to unique requested IDs. Metadata reads are bounded to 256 KiB. Malformed/oversized/inaccessible results hold unsettled reservations as unknown; they never become a zero charge. Migration 24 journals up to three file IDs per batch. The input ID is saved before batch creation; polling journals input/output/error IDs before reading. Only after terminal results are durably reconciled does cleanup DELETE those exact files. Failed deletions remain pending and retry on the existing batch poll path, including after process restart, without rereading deleted outputs. Terminal batch states reject delayed status updates, so a racing stale poll cannot downgrade already reconciled results. Unknown billing preserves provider files for recovery until their configured expiry. A submission whose outcome is uncertain is never automatically resubmitted.

Input and output/error files explicitly expire 48 hours after each file's creation. This is a reversible implementation default for bounded retention, long enough for the 24-hour batch window, not a claim of owner research approval or live verification. It covers abandoned uploads/unknown batch creation where a crash prevents recording a provider batch ID. Expired missing results still require cost reconciliation. Existing batch input files can also be discovered through the provider batch record on polling. No real provider file was uploaded or deleted during this work.

Provider contract checked October 20, 2026 against official references: [file expiry](https://developers.openai.com/api/reference/resources/files/methods/create), [output/error expiry](https://developers.openai.com/api/reference/resources/batches/methods/create), [file deletion](https://developers.openai.com/api/reference/resources/files/methods/delete). Only loopback HTTP doubles exercised these contracts.

## Operation and remaining limits

Run pnpm db:migrate on an explicitly selected deployment database when adopting the change. Reverify/repackage artifacts affected by the bridge hash change. Use the existing context-batch polling command to reconcile and retry pending cleanup. Batch file deletion failures do not undo saved local results or release unknown exposure. The expiry fallback is finite; an offline studio can lose remote result availability and must reconcile cost through provider records.

This repair establishes local/fixture/contract behavior and the new native QA boundary. It does not establish live processor/OpenAI behavior, hosted readiness, Tauri acceptance or empirical study validity.
