## Everyday path

1. Start the web studio using [local development](LOCAL_DEVELOPMENT.md), or use an already
   accepted installed Windows candidate. Sign in and choose the intended workspace.
2. In Models and connections configure supported access, review caps and allowed data/work,
   and qualify the exact role prompt. A historic pass can be retained without qualifying the
   current prompt; the page labels this. Fixture workspaces remain visibly synthetic.
3. Use Sources to record inspectable passages and claims. A typed theme is not evidence and
   does not automatically search. Discover accepts a brief/theme draft; Explore for me uses
   recorded claims with a preview of exactly what will be sent.
4. Compare the alternatives, inspect evidence and disagreements, and record the decision,
   scorecards and humility review. Existing tools, process changes, human-led action and
   defer/decline remain legitimate outcomes.
5. For a selected software option, freeze the spec and bounded checks, build/review/QA through
   the isolated worker, then inspect the exact package/preview and give feedback. Startup
   from an exported package and a worktree test are different evidence.
6. Use Monitor for runs, budgets, activity and recovery. Unknown requests/costs need
   reconciliation; retrying is not evidence that the earlier action did not happen.

Windows desktop, scoped GitHub, hosted, commerce and campaign code exists, with differing
fixture, contract, native and live evidence. None is activated simply by reading this guide.
