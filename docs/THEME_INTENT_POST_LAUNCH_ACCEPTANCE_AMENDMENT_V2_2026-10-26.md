## R1: mandatory current-work safety prerequisite

No prospective worker-on launch is admissible solely because the owner accepts
unknown queued/uncertain work. Current-work safety support is mandatory before
any launch, including an identification-only launch. An after-launch UI baseline
cannot establish safety before the worker starts. PR-01's sampled stopped state,
the reported absence of intentional edits, and M3's scheduler-off configuration
do not establish this prerequisite, individually or together.

The next repository-only design must answer this exact question: for the installed
candidate, can every automatic startup/worker/outbox/broker/retrieval path be shown
either unable to execute work outside the proposed session scope or subject to
effective deterministic admission with matching authority and bounded exposure,
including existing queued, leased and uncertain outcomes? Enumerate the real
paths and evidence locators; do not assume scheduler-off disables the worker.

One coherent method must be selected and independently reviewed before any
operational capability is implemented or used:

- A bounded current-work inspection, only if it can establish the required
  predicates without an out-of-order worker-on launch and with a defined validity
  interval and exclusion of intervening producers. Specify exact records/states,
  nonsecret outputs, observer effects, failure semantics, resource bounds and
  any required credential/cluster-start authority. No SQL, credential acquisition
  or cluster start is authorized by naming this option.
- An effective startup admission/control path, if inspection cannot establish or
  preserve those predicates. This would be a changed candidate with separate
  implementation/review/package/install decisions; preserve old evidence rather
  than implying it verifies changed bytes.
- Equivalent exact-source safety evidence, only if it covers every relevant
  automatic work path and deterministic action/resource admission for this exact
  installed candidate. Source assertions or lack of visible activity alone fail.

These are bounded design alternatives, not three implementation milestones.
Prefer existing reviewed mechanisms where their actual coverage suffices. If none
can support safety within authorized scope, defer native acceptance. Owner judgment
can select an evidence approach and accept reporting limitations; it cannot grant
unspecified dispatch, waive deterministic admission or turn unknown exposure into
zero. This document does not claim an actual bypass, damage or dispatch occurred.
